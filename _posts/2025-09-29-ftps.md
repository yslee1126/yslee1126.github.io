### 개요 
- 레거시 FTP 서버에 보안상의 이유로 FTPS 가 설정된 경우 FTPS 를 지원하는 클라이언트로 교체한다  
- 기존에 commons-net 을 사용하고 있었기 때문에 라이브러리 의존성은 그대로 유지 

### FTPS vs SFTP 

- sftp 와 헷갈리지 말자 

| 구분 | FTPS | SFTP |
| --- | --- | --- |
| 풀네임 | File Transfer Protocol Secure | SSH File Transfer Protocol |
| 기반 | 기존 FTP + TLS/SSL 암호화 | SSH(Secure Shell) 위에서 동작 |
| 포트 | 기본 21 (명령) + 20 (데이터)<br/>또는 임의의 데이터 포트 필요 | 기본 22 (SSH와 동일) |
| 보안 방식 | TLS/SSL 인증서 (X.509 인증서 필요) | SSH 키 또는 ID/PW 인증 |
| 연결 방식 | 명령 채널 + 데이터 채널 2개 연결 | 단일 채널 (SSH 하나로 처리) |
| 방화벽/네트워크 | 데이터 채널 때문에 방화벽 설정이 까다로움 | 포트 22 하나만 열면 됨, 방화벽 친화적 |
| 사용 예시 | 기업에서 기존 FTP 서버를 보안 추가해서 유지할 때 | 서버 관리, 리눅스 환경, 클라우드 업로드 등에 많이 사용 |

### Client 코드 

- 클라이언트 생성하는 부분
- 로그인 이후에 선언하는 옵션들은 순서를 지켜가면서 선언되어야 한다 

```java

public FTPSClient createFtpsClient(FtpInfo ftpInfo) {

  FTPSClient ftpClient = new FTPSClient(false); // implicit false => 기본 FTP로 접속 후, AUTH TLS 명령으로 암호화 전환
  ftpClient.setConnectTimeout(ftpInfo.getConnectTimeout()); 
  ftpClient.setDataTimeout(ftpInfo.getReadTimeout());

  ftpClient.setUseEPSVwithIPv4(false); // IPv4에서 EPSV(Extended Passive Mode) 비활성화
  ftpClient.setRemoteVerificationEnabled(false); // 원격 검증 비활성화, 제어 연결과 데이터 연결의 IP가 달라도 허용

  ftpClient.setEndpointCheckingEnabled(false); // SSL/TLS 인증서의 엔드포인트 검증 느슨하게, CN과 호스트명이 달라도 연결 허용, IP 로 접속 가능  

  ftpClient.setEnabledProtocols(new String[] {"TLSv1.2", "TLSv1.3"}); // 명시적으로 최신 프로토콜만 사용 
  ftpClient.setControlKeepAliveTimeout(300); // 5분마다 제어 연결 유지
  ftpClient.setControlKeepAliveReplyTimeout(ftpInfo.getReadTimeout());

  /* 접속 과정 로깅하고 싶을때
  ftpClient.addProtocolCommandListener(
          new PrintCommandListener(new PrintWriter(System.out), true)
  );
  */

  try {
    // 연결 시도
    ftpClient.connect(ftpInfo.getHost(), Integer.parseInt(ftpInfo.getPort()));
    int replyCode = ftpClient.getReplyCode();
    if (!FTPReply.isPositiveCompletion(replyCode)) { // 200~299 범위의 성공 응답 확인
      ftpClient.disconnect();
      replyCode = tryReconnection(ftpClient, ftpInfo);
      if (!FTPReply.isPositiveCompletion(replyCode)) {
        log.warn("FTPServer refused connection,replyCode:{}", replyCode);
      }
    }

    if (!ftpClient.login(ftpInfo.getUser(), ftpInfo.getPasswd())) {
      log.warn("ftpClient login failed... username is {}; password: {}", ftpInfo.getUser(), ftpInfo.getPasswd());
    }

    ftpClient.setBufferSize(ftpInfo.getBufferSize());
    ftpClient.setFileType(ftpInfo.getTransferFileType()); // 이미지, 압축 파일 등
    if (ftpInfo.isPassive()) {
      ftpClient.enterLocalPassiveMode(); // 클라이언트가 서버로 데이터 연결 시도 (방화벽 친화적)
    }

    // 데이터 연결 보호 모드 설정
    ftpClient.execPBSZ(0); // Protection Buffer Size 설정, TLS 사용 시 필수로 0으로 설정 (버퍼 크기 무관) 
    ftpClient.execPROT("P"); // P : 데이터 채널도 암호화 (가장 안전), C : 제어 채널만 암호화, 데이터는 평문

  } catch (IOException e) {
    log.error("FTPS 연결 실패: {}", e.getMessage(), e);
  }
  return ftpClient;
}


```

if (ftpClient != null && ftpClient.isConnected()) {
  try {
    ftpClient.logout();
      } catch (IOException ex) {
            log.error("Failed to logout FTP client", ex);
      } finally {

### 회고 
- ftp 는 방화벽 설정과 옵션설정을 서버측과 정확히 맞춰야한다 
  - 옵션을 맞춰야 한다는 번거로움이 크고 서버 확장이 불편하다 
  - 병렬처리는 commons-pool 을 사용하는 것으로 가능하다  
- 파일 전송은 추후 http 기반으로 전환하는게 MSA 구조에 적합할 것 같다
  - 방화벽 문제, 인증, 병렬처리 등 이슈를 현대적으로 해결 가능 
  - 그러나 큰 파일도 청크 단위로 나눠서 전송할 수 있는지는 좀더 확인이 필요하다
